# addons/

Umbrella (wrapper) charts that configure components we **do not develop in-house**: Argo CD, cert-manager, Cilium,
Crossplane, Kyverno, Harbor, Istio, OpenChoreo's planes and so on. Each addon pins the upstream chart as a dependency
and adds only our values plus the small templates that component needs on this platform (policies, RBAC,
ClusterSecretStores, PodMonitors). Platform logic we write ourselves lives in [`charts/`](../charts/README.md).

| Pattern | Where |
|---|---|
| Upstream chart + digest-pinned images | `Chart.yaml` dependency, `values.yaml` |
| Per-cluster variants, picked by cluster-secret labels | `values/role-*.yaml`, `values/provider-*.yaml`, `values/cni-*.yaml` |
| Installation overrides (values only, never templates) | `installations/<inst>/addons/<addon>.yaml` |
| Which clusters get it | catalog in [`charts/platform/values.yaml`](../charts/platform/values.yaml) |
| Docs | per-addon `README.md`, generated by `helm-docs` from `README.md.gotmpl` + `values.yaml` |

Three addons have no upstream dependency and only render configuration for an upstream component: `coredns-local`
(k3s CoreDNS), `openchoreo-platform` (OpenChoreo org, pipeline, component types, workflows) and `secret-stores`
(External Secrets Operator stores).

**Crossplane** is an addon too: [`crossplane/`](crossplane/README.md) installs Crossplane v2 and ships the platform's
PostgreSQL API (XRD in `templates/xrd-postgresql.yaml`, one Composition per backend in `compositions/`). Why these are
chart templates and not a Crossplane Configuration package: [docs/data-services.md](../docs/data-services.md).
