# charts/

Platform charts **we develop in-house**: the glue between Argo CD, Cluster API and OpenChoreo. They contain no
upstream component; the components themselves are configured by the wrapper charts in
[`addons/`](../addons/README.md).

| Chart | What it does | Rendered by |
|---|---|---|
| [`platform/`](platform/README.md) | Root chart: AppProjects, ApplicationSets (fleet, addon catalog, tenants), mgmt cluster secret | bootstrap (`task up`), then Argo CD |
| [`cluster/`](cluster/README.md) | Cluster API: scope `fleet` (providers, credentials, ClusterClasses per provider) and scope `cluster` (one workload cluster: CAPI Cluster, Argo CD registration, OpenChoreo data plane, mesh) | fleet ApplicationSet, per `installations/<inst>/clusters/*.yaml` |
| [`tenant/`](tenant/README.md) | One OpenChoreo tenant: AppProject, OpenChoreo Project, one Argo CD Application per app repo, PR preview ApplicationSet | tenant ApplicationSet, per `installations/<inst>/tenants/*.yaml` |
| [`preview/`](preview/README.md) | One PR preview environment: OpenChoreo Environment, ProjectReleaseBinding, ReleaseBinding pinning the PR head build | preview ApplicationSet, per open pull request |
| [`lib/`](lib/README.md) | Library chart `koorikla-lib`: named templates that several charts and addons render identically (agent server CA, operator namespace labels, ESO kubernetes-provider stores, AppProject sourceIntegrity) | consuming charts, as `file://` dependency |
| [`lib-test/`](lib-test/README.md) | helm-unittest harness for `lib/` (a library chart renders nothing on its own) | `task test` only, never deployed |

Every chart has a `README.md` generated by `helm-docs` from `README.md.gotmpl` + `values.yaml`, and unit tests in
`tests/` (helm-unittest, run by `task test`).
